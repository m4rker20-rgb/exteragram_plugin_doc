# 13. PIP и зависимости

Внешние Python-библиотеки в плагинах через встроенный менеджер пакетов.

## Объявление зависимостей

Перечислите пакеты в метаданных `__requirements__` (формат — стандартный PEP 508):

```python
__id__ = "inline_calculator"
__name__ = "Inline Calculator"
__requirements__ = ["mpmath", "tinydb"]

from base_plugin import BasePlugin, HookResult, HookStrategy
from mpmath import mp
from tinydb import TinyDB

class CalculatorPlugin(BasePlugin):
    ...
```

При установке плагина пользователем exteraGram автоматически скачает эти библиотеки и их зависимости.

## Как это работает

- **Резолюция:** система запрашивает метаданные PyPI, чтобы найти версию, удовлетворяющую ограничениям.
- **Только pure-Python:** скачиваются только «универсальные» колёса (`-none-any.whl`).
- **Изоляция:** библиотеки ставятся в общую папку `libs`; одинаковая версия для нескольких плагинов скачивается один раз.
- **Автоочистка:** при удалении плагина зависимости, не нужные больше никому, удаляются автоматически.

## Ограничения

### 1. Нет бинарных расширений — главное ограничение

Популярные библиотеки с C/C++-расширениями (`numpy`, `pandas`, `scipy`, `cryptography`, `opencv`) **не установятся**: им нужна компиляция под конкретную архитектуру Android и линковка с рантаймом приложения.

- ✅ Разрешено: пакеты с «Universal» / `none-any` в имени колеса.
- ❌ Запрещено: пакеты с платформенными колёсами (`manylinux`, `macosx`, `win_amd64`) или скомпилированными компонентами.

### 2. Конфликты зависимостей

В отличие от виртуального окружения, все плагины делят один набор установленных библиотек:

- Плагин A требует `requests==2.25.1`, плагин B — `requests==2.31.0` → конфликт.
- Система попытается найти версию, устраивающую обе стороны; если такой нет — установка второго плагина упадёт.

### 3. Сеть

Установка требует интернета для доступа к `pypi.org`.

### 4. Ограниченная поддержка маркеров

Базовые маркеры окружения (`python_version`, `sys_platform`) поддерживаются; сложные маркеры и `extra` могут не работать.

## Предустановленные библиотеки

Некоторые библиотеки уже установлены в приложении — их можно импортировать без `__requirements__` (но указать не вредно):

| Библиотека | Назначение |
|---|---|
| `requests` | HTTP-запросы |
| `pillow` | Обработка изображений (PIL) |
| `beautifulsoup4` | Парсинг HTML/XML, веб-скрейпинг |
| `lxml` | Быстрая обработка XML/HTML |
| `PyYAML` | YAML-парсер и эмиттер |
| `packaging` | Утилиты для версий пакетов |
| `debugpy` | Официальный Python-отладчик (используется DevServer) |

## Troubleshooting

| Ошибка | Причина и решение |
|---|---|
| `No pure-Python wheel found` | Библиотека содержит скомпилированный код. Использовать нельзя, пока она не встроена в ядро приложения. Ищите pure-Python замену |
| `Dependency conflict` | Другой установленный плагин использует несовместимую версию той же библиотеки |
| `Package not found` | Проверьте написание имени пакета и его доступность на PyPI |

## Зависимости в Elyx-плагинах

В Elyx используется строковая форма (`requirements: "requests>=2.32"`) плюс два дополнительных механизма — бандл-колёса (`wheels:`) и зависимости на другие плагины (`requires:`). Подробно — в [11. Elyx](11-elyx-structured-plugins.md#зависимости).
