# 17. FAQ и Troubleshooting

Частые ошибки, вопросы и способы диагностики.

## Общие проблемы

### Плагин не появляется в списке / не устанавливается

- Проверьте метаданные: `__id__` и `__name__` обязательны, `__id__` — 2–32 символа, с буквы, `[a-zA-Z0-9_-]`;
- метаданные — простые литералы верхнего уровня (AST-парсинг; динамические значения не читаются);
- версия приложения: SDK 1.4.4.3 требует exteraGram **12.5.1+**; на старых сборках SDK уходит в safe mode;
- движок плагинов включён в настройках exteraGram.

### Плагин включён, но ничего не делает

- Хук реализован, но не зарегистрирован? `on_send_message_hook` требует `self.add_on_send_message_hook()` в `on_plugin_load`; event-хуки — `self.add_hook("TL_...")`;
- смотрите лог: `adb logcat -s plugin.<id>`;
- исключение в `on_plugin_load` не всегда видно в UI — логгер покажет трейсбек (`self.logger.exception(...)`).

### `ImportError` при старте

- Импорты SDK допустимы только внутри рантайма приложения — на десктопе модуль не запускается (используйте заглушки `exteragram-utils` только для IDE);
- установились ли зависимости? Ошибки PIP показываются при установке плагина (см. [13](13-dependencies.md));
- не теньте ли вы стандартную библиотеку или SDK-модули именем своего файла (например, `json.py`, `requests.py` в корне плагина)?

### Ошибки версий (`TypeError` на account-хелперах)

Account-хелперы (`self.client()`, `get_client()`, `get_hook_account()`, `get_selected_account()`, параметры `account=`) требуют **SDK 1.4.5.0+**. Заявите `__sdk_version__ = ">=1.4.5.0"`, чтобы старые установки падали с понятным сообщением.

`IntentsManager` требует exteraGram **66999 (12.6.4)+**. `custom_name` для class proxy — version code **≥ 66690**.

## Логи и диагностика

```bash
# Логи конкретного плагина:
adb logcat -s plugin.my_plugin

# Только ошибки:
adb logcat *:E

# Дамп структуры объекта в буфер обмена для инспекции:
copy_to_clipboard(dump(message.messageOwner, depth=4))
```

- нет логов вообще → проверьте, что плагин включён; включите developer mode (иначе DEBUG скрыт);
- долгие записи logcat логгер сам режет на части по строкам;
- логируйте аргументами (`self.logger.debug("chat %s", chat_id)`), а не f-строками — в горячих хуках это заметно дешевле.

## Проблемы хуков

| Симптом | Причина |
|---|---|
| Хук не срабатывает | Не вызван `self.add_hook(...)` / `add_on_send_message_hook()`; неверное имя TL-метода |
| Хук срабатывает «не для того аккаунта» | Это норма: фоновые аккаунты тоже шлют запросы. Действуйте через `self.client(account)` |
| `params.message` отсутствует | Отправка без текста (медиа). Проверяйте `isinstance(getattr(params, "message", None), str)` |
| Изменение не применяется | Не установлен `HookResult(strategy=HookStrategy.MODIFY, ...)` с изменённым объектом в нужном поле (`request`/`response`/`update`/`params`) |
| Другие плагины перестали получать хук | Вы вернули `HookStrategy.MODIFY_FINAL` — он останавливает дальнейшую обработку события |
| Xposed-хук не ставится | `find_class` вернул `None` (класс переименовали в этой версии); неверная сигнатура в `getDeclaredMethod`; метод в родителе, а ищете declared |

## Проблемы UI

| Симптом | Причина |
|---|---|
| Диалог/буллетин не показывается | Нет активного фрагмента/активити; проверьте `get_last_fragment().getParentActivity()` |
| Приложение крашится при изменении UI | Мутация UI не с UI-потока: оберните в `run_on_ui_thread(...)` |
| Настройка не сохраняется | У контрола нет `key`; или читаете другой ключ, чем записали |
| Экран настроек не обновился после `set_setting` | Нужен `reload_settings=True` (или дождитесь переоткрытия экрана) |
| Кастомная фабрика течёт памятью | Фабрика создаётся при каждом `create_settings()`; создайте её один раз на уровне модуля |

## Class Proxy

| Симптом | Проверить |
|---|---|
| `super()` не работает | Метод объявлен через `@joverride(...)`/`@joverload(...)` |
| Оверлоад не вызывается | Типы аргументов совпадают с реальной Java-сигнатурой; примитивы — `"int"`, а не `Integer` |
| Генерация класса падает | Базовый класс `final`? Сигнатуры конструктора существуют? |
| Поле всегда `None` | `jfield` объявлен, тип валиден, default совместим |

## Elyx

### Архив не распознаётся

- расширение: `.elyx`, `.eaf`, `.elyx.zip`, `.eaf.zip`;
- `refmap.yml` **в корне архива** (не во вложенной папке);
- архив докачан полностью и является валидным ZIP.

### «Metainfo not found» / «Main file not found»

- пути в `refmap` относительны корня архива и **регистрозависимы** на Android;
- если `main` опущен — автоматически ищется только корневой `main.py`;
- YAML/JSON должен парситься в маппинг и быть непустым.

### «No BasePlugin subclass found»

Во входном модуле должен быть конкретный подкласс `BasePlugin`, не спрятанный за условием, ложным при импорте. Один класс плагина на входной модуль.

### Локальный импорт падает

- регистр имени файла совпадает точно;
- для вычисляемых имён — `from elyx import import_module`, а не `importlib`;
- не создавайте пакеты с именами `elyx`, `ui`, `java`, `android`, `base_plugin`, `client_utils`, `hook_utils`, `org`, `com`, `de`, `androidx`, `importlib`.

### `from elyx import assets/strings` падает

Компонент окружения существует только при валидном пути в `refmap` (`assets:`/`strings:`) и непустом содержимом. Для опциональных — `get_environment().get("assets")`. Всегда включайте `strings_en` (английский — fallback).

### Перевод возвращает свой ключ

Это финальный fallback: ключа нет ни в выбранной локали, ни в английской. Проверьте совпадение ключей и плейсхолдеров (`{name}`).

### Live reload: «plugin not found»

Плагин должен быть уже установлен и загружен: локальный `id` совпадает с установленным, архив ставился минимум один раз, движок завершил старт, `adb forward tcp:42690 tcp:42690` создан, плагин виден в `get_elyx_plugins`. После смены `id` — переустановите архив.

### Reload прошёл, но поведение старое

Elyx чистит плагин-локальные модули, но глобальное состояние выживает: фоновые потоки не остановлены в `on_plugin_unload`; слушатели зарегистрированы вне SDK-API; monkey-patch'и чужих модулей; кеш в сторонних модулях. Переносите init в `on_plugin_load`, cleanup — в `on_plugin_unload`; для финальной диагностики перезапустите приложение.

### Бандл-колесо не обновляется

Elyx идентифицирует извлечённое колесо по **stem имени файла**: содержимое изменилось → соберите колесо с новой версией/именем (`my_lib-1.0.1-...whl`), а не перезаписывайте старое.

## Проблемы подключения DevServer

- сервер включён + developer mode включены в приложении;
- `adb devices` видит устройство;
- пересоздайте forward: `adb forward --remove tcp:42690 && adb forward tcp:42690 tcp:42690`;
- порт `42690` на ПК не занят другим процессом;
- после смены устройства — перезапустите сервер;
- `ping` работает, а `elyx_ping` нет → сервер работает, но Elyx-патч не инициализировался.

## Как сообщать о проблемах SDK / Elyx

Прикладывайте: версию exteraGram, версию SDK, версию Elyx, Android-версию и ABI устройства, метаданные и `refmap` плагина, минимальный архив/дерево проекта, полный Python-трейсбек, на каком этапе воспроизводится (чистая установка / enable / reload / update). Уберите из логов токены, персональные данные и приватные URL.

Полезные места сообщества: [exteraSquad](https://github.com/exteraSquad) (SDK), [официальная документация](https://plugins.exteragram.app/docs), каталоги плагинов ([extragram_plugins](https://github.com/fan-world-me/extragram_plugins), [awesome-telegram-plugins](https://github.com/makarworld/awesome-telegram-plugins)).
